       ```
       If no run is listed within ~30 seconds of the push, STOP and surface the issue — the workflow file may have YAML errors GitHub silently rejected.

    2. Poll the run's status until it is no longer `in_progress` / `queued`. Use `gh run watch`:
       ```
       RUN_ID=$(gh run list --repo actowery/coverage-is-a-lie --workflow CI --branch main --limit 1 --json databaseId --jq '.[0].databaseId')
       gh run watch "$RUN_ID" --repo actowery/coverage-is-a-lie --exit-status
       ```
       `--exit-status` makes `gh run watch` exit non-zero if the conclusion is anything other than `success`. The watch will block until the run finishes (typically ~60 seconds for a minimal `bundle install` workflow per VALIDATION §"Test Infrastructure").

    3. After the watch returns, double-check the conclusion explicitly:
       ```
       gh run list --repo actowery/coverage-is-a-lie --workflow CI --branch main --limit 1 --json conclusion --jq '.[0].conclusion'

       Must print exactly `success`.

    4. If the run conclusion is anything else (`failure`, `cancelled`, `timed_out`, `action_required`, `neutral`, `skipped`), surface the run URL and the last 50 lines of the failed job's log:

       gh run view "$RUN_ID" --repo actowery/coverage-is-a-lie --log-failed | tail -50
