**Rakefile:**

Create `Rakefile` at the repo root. Content:

```ruby
# frozen_string_literal: true

require "rspec/core/rake_task"

RSpec::Core::RakeTask.new(:spec)

task default: :spec
```

This makes `bundle exec rake` and `bundle exec rake spec` both run the RSpec suite. Do NOT add mutant tasks here — those are Phase 3.

---

**CI workflow update:**

Read the current `.github/workflows/ci.yml` (established in Phase 1). It has one job: `bundle` which runs checkout + setup-ruby with bundler-cache but no test step.

Replace the file with an updated version that has TWO jobs:

1. `bundle` job — unchanged from Phase 1 (checkout + setup-ruby + bundler-cache). This job is the fast dependency cache gate.

2. `rspec` job — depends on nothing (can run in parallel with other future jobs; setup-ruby's bundler-cache handles gem availability). Steps:
   - `uses: actions/checkout@v6`
   - `uses: ruby/setup-ruby@v1` with `ruby-version-file: .ruby-version` and `bundler-cache: true`
   - `name: Run RSpec` / `run: bundle exec rspec`

Do NOT set `COVERAGE=1` in CI — the `minimum_coverage 100` check in spec_helper is guarded by `ENV["COVERAGE"]` exactly so that CI can run tests cleanly without requiring the coverage minimum. SimpleCov does not load at all unless COVERAGE is set. This is intentional (LIB-07 demo setup: coverage report is run locally to show the green dashboard, not enforced in CI where it would gate on the very weakness we're demonstrating).

Do NOT add `--format documentation` to the rspec run — keep output compact for CI logs.

The updated ci.yml:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  bundle:
    name: bundle install
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: ruby/setup-ruby@v1
        with:
          ruby-version-file: .ruby-version
          bundler-cache: true

  rspec:
    name: RSpec
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: ruby/setup-ruby@v1
        with:
          ruby-version-file: .ruby-version
          bundler-cache: true
      - name: Run RSpec
        run: bundle exec rspec
```

Write this exact content. The `bundle` job is intentionally kept as a separate job (not merged with rspec) because Phase 3 will add a `mutant` job alongside `rspec`, and keeping them separate preserves parallelism.
