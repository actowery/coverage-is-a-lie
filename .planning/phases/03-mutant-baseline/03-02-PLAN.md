<task type="auto" tdd="false">
  <name>Task 1: Create tmp/ directory and run mutant with output capture</name>
  <files>tmp/mutant-report.txt</files>
  <action>
Ensure the `tmp/` directory exists (mkdir -p). Then run the following command with a 600-second hard timeout using Ruby's timeout wrapper or the `timeout` shell command:

  timeout 600 bundle exec mutant run --integration rspec DateUtils 2>&1 | tee tmp/mutant-report.txt

The `2>&1` redirect captures both stdout (mutation progress) and stderr (mutant boot messages, any Ruby warnings) into a single stream. `tee` writes to the file while also printing to the terminal so progress is visible.

Exit code behavior: mutant exits 1 when any mutations survive (which is expected here — the weak tests are designed to let boundary mutations through). A non-zero exit from mutant does NOT indicate a problem; treat exit codes 0 and 1 as both success for this plan. Only exit code from `timeout` command itself indicating a timeout kill (124 on most systems) should be treated as a failure.

If the `timeout` binary is not available on the system (macOS does not include GNU timeout by default), use the Ruby alternative:
  bundle exec ruby -e "require 'timeout'; Timeout.timeout(600) { exec 'bundle exec mutant run --integration rspec DateUtils' }" 2>&1 | tee tmp/mutant-report.txt

On macOS with Homebrew, `gtimeout` (from coreutils) may also be available. Check with `which gtimeout` first; if present use `gtimeout 600`.

After the run completes, verify `tmp/mutant-report.txt` is non-empty and contains at least one of the expected surviving-mutation markers.

Do NOT set COVERAGE=1 — SimpleCov must not load during this run (MUT-04).
Do NOT pass --fail-fast — all mutations must be evaluated to produce a complete report.
