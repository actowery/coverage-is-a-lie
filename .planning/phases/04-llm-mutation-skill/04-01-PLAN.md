The script at `.claude/skills/llm-mutate/scripts/run_mutant_spec.sh` must implement this exact logic:

1. Accept one positional argument: the path to a mutated Ruby source file (e.g. `tmp/mutants/LM-DB-01.rb`).
2. Validate that exactly one argument was passed. If not, print "Usage: run_mutant_spec.sh <mutant_file>" to stderr and exit 2.
3. Validate that the mutant file exists and is readable. If not, print an error to stderr and exit 2.
4. Save the original library: `cp lib/date_utils.rb .claude/skills/llm-mutate/tmp/date_utils.orig.rb`
5. Register a trap on EXIT to restore the original: `trap 'cp .claude/skills/llm-mutate/tmp/date_utils.orig.rb lib/date_utils.rb' EXIT`
   This trap fires on normal exit, on error (set -e), and on SIGINT/SIGTERM — the library is always restored.
6. `set -euo pipefail` at the top of the script (after the shebang and before the arg check).
7. Install the mutant: `cp "$1" lib/date_utils.rb`
8. Run the test suite and capture its exit code: `bundle exec rspec --no-color --format progress 2>&1`
9. Capture the exit code with `RSPEC_EXIT=$?`.
10. Exit with `$RSPEC_EXIT`. The trap runs on exit and restores the original.
    Exit 0 means RSpec passed = the mutation SURVIVED (tests did not catch the change).
    Exit non-zero means RSpec failed = the mutation was KILLED (tests caught it).

Wait — the requirement is "exit 0 if RSpec passes (mutation killed) and exit 1 if it fails (mutation survived)". Re-reading SKILL-11: "exits 0 if RSpec passes (mutation killed) and 1 if it fails (mutation survived)". This is inverted from the normal RSpec convention. The script should therefore invert: if rspec exits 0 (pass), script exits 0 (mutation killed). If rspec exits non-zero (fail), script exits 1 (mutation survived). So the exit semantics match rspec directly — do not invert. Killed = rspec passes = exit 0; survived = rspec fails = exit 1.

The shebang must be `#!/usr/bin/env bash`. Mark the file executable with `chmod +x`.

Add `--require spec_helper` handling: run rspec as `bundle exec rspec spec/date_utils_spec.rb --no-color --format progress` to avoid loading any other spec files.

Do NOT suppress rspec output entirely — pipe stdout+stderr to /dev/null only in --generate mode batch runs. In this script, capture output to a variable (using `$()` or a temp file) but do not print it unless the caller wants it. Actually: redirect all rspec output to /dev/null for clean batch operation. The report rendering step reads verdicts, not rspec output.

Final implementation:

```
#!/usr/bin/env bash
set -euo pipefail

MUTANT_FILE="${1:-}"
ORIG_BACKUP=".claude/skills/llm-mutate/tmp/date_utils.orig.rb"

if [[ -z "$MUTANT_FILE" ]]; then
  echo "Usage: run_mutant_spec.sh <mutant_file>" >&2
  exit 2
fi

if [[ ! -f "$MUTANT_FILE" ]]; then
  echo "Error: mutant file not found: $MUTANT_FILE" >&2
  exit 2
fi

mkdir -p .claude/skills/llm-mutate/tmp

cp lib/date_utils.rb "$ORIG_BACKUP"
trap 'cp "$ORIG_BACKUP" lib/date_utils.rb' EXIT

cp "$MUTANT_FILE" lib/date_utils.rb

bundle exec rspec spec/date_utils_spec.rb --no-color --format progress > /dev/null 2>&1
RSPEC_EXIT=$?

exit $RSPEC_EXIT
```
